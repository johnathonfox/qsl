# Security and correctness audit — 2026-10-10

Full-codebase review of `main` at `56a3d57`, covering every crate
and both apps. Each finding was traced end to end in source before it
was recorded; the sanitizer findings were additionally reproduced
against the exact `ammonia` 4.1.2 / `html5ever` 0.35 in the lock file,
and the `jmap-client` findings against its 0.4.1 source.

Status legend: **Fixed** — landed in the same change set as this
report, with regression tests where the shape allowed. **Open** —
not addressed here; see "Deferred" for why and for the suggested fix.

## Summary

| Severity | Fixed | Open |
|----------|-------|------|
| Critical | 3     | 0    |
| High     | 8     | 1    |
| Medium   | 14    | 8    |
| Low      | 11    | ~15  |

The three criticals were: two IMAP accounts destroying each other's
local cache, the `Bcc:` header being transmitted to every recipient,
and SMTP header injection reachable from a crafted inbound subject
via Reply.

---

## Critical

### C1 — Folder and message ids were not account-scoped (Fixed)
`folders.id` / `messages.id` are global primary keys, but the IMAP
backend minted folder ids from the bare mailbox path and message ids
as `imap|<uv>|<uid>|<path>`. With two accounts, the second account's
`sync_folder` found the first account's `INBOX` row, re-pointed its
`account_id`, shared its sync cursor, and the reconciliation pass
pruned the other account's messages as server-deleted — every cycle,
alternating. Gmail's small UIDVALIDITY values make message-id
collisions likely too.
**Fix:** `FolderId::scoped(account, key)` = `<account_id>|<key>` on
both backends; `FolderId::backend_key` recovers the wire name; IMAP
message ids embed the scoped folder. Account emails are validated
(`AccountId::for_provider`) so the separator can never appear in the
prefix. Migration 0019 resets the cached tree (see CHANGELOG).
Files: `crates/core/src/ids.rs`, `crates/imap-client/src/{backend,idle}.rs`,
`crates/jmap-client/src/lib.rs`, `apps/mailcli`, UI label helpers,
`crates/storage/migrations/0019_account_scoped_folder_ids.sql`.

### C2 — `Bcc:` header transmitted to all recipients (Fixed)
`build_rfc5322` writes `Bcc:` into the bytes and the IMAP
`submit_message` sent those same bytes as SMTP `DATA`.
**Fix:** `qsl_mime::compose::strip_bcc_header` removes the header
(incl. folded lines) from the wire bytes; the Sent-folder APPEND keeps
the full copy. JMAP servers strip Bcc at submission per RFC 8621.

### C3 — SMTP/MIME header injection via CR/LF (Fixed)
mail-builder passes a short ASCII subject through verbatim and writes
addr-specs raw between `<…>`. An inbound `Subject:
=?us-ascii?Q?Hi=0D=0ABcc:=20evil@x?=` decodes to a CRLF, Reply
prefixes `Re: `, and Send emits an injected `Bcc:` that
`extract_envelope` then honours as an envelope recipient. Also
reachable locally via `mailto:?subject=…%0D%0A…`.
**Fix:** `build_rfc5322` rejects CR/LF/NUL in subject, addresses,
display names, attachment names/types, In-Reply-To and References,
and validates addr-spec shape; inbound decoded headers have those
bytes neutralised (`strip_header_controls`).

## High

### H1 — Sanitizer panicked on non-ASCII `style` values (Fixed)
`css_url_tokens` stepped byte-by-byte and sliced `decl[i..]` inside a
multi-byte char. `font-family: Söhne` or `margin:0&nbsp;auto` panicked
the render task; the IPC promise never resolved and the reader (or a
whole thread) stayed on "Loading…". Rewritten on `char`s.

### H2 — Inline-style remote-content filter bypassable (Fixed)
`URL(`, `\75rl(`, `url/**/(`, a `;` inside the quoted URL, and
`image-set("…")` all slipped past the literal `url(` scan while the
reader CSP's `img-src https:` let the fetch through — per-recipient
open tracking from an untrusted sender. Rewritten with comment
stripping, CSS-escape decoding, lowercase matching, quote/paren-aware
declaration splitting, and a fetching-function list
(`url image-set -webkit-image-set image src cross-fade element paint
@import`). Malformed declarations are dropped conservatively.

### H3 — Dropped transaction poisoned later autocommit writes (Fixed)
`TursoTx::drop` only set a flag; the recovery `ROLLBACK` ran at the
next `begin()`. Every autocommit `execute` in between joined the
orphan `BEGIN` and was discarded — e.g. the outbox drain's
"delete after send", so the row came back and the message was sent
twice. Recovery now runs on `execute`/`query` too.

### H4 — JMAP session URL doubled, redirects refused (Fixed)
`jmap-client` appends `/.well-known/jmap` itself and rejects every
redirect unless the host is trusted. Fastmail connect could never
succeed. `dial_client` normalises the origin, trusts exactly that
host, and raises the 10 s request timeout to 120 s.

### H5 — JMAP writes used QSL's local `AccountId` as the server accountId (Fixed)
`save_draft` / `submit_message` → `accountNotFound`. Now use the
session's default account.

### H6 — Outbox drain and watchers never started on a fresh install or offline boot (Fixed)
`run()` returned before spawning the drain when no account produced
folders, and never re-ran discovery. Sends, flag changes, moves and
draft uploads sat in the outbox until restart. Drain now starts
first and unconditionally; discovery loops on `accounts_changed` /
a 60 s retry.

### H7 — `cid:` rewrite had unbounded output amplification (Fixed)
`str::replace` of every `cid:x` (text nodes included) with a full
base64 part: 20 MB part × 2000 mentions ≈ 54 GB → abort. Now
whole-id matches with a terminator check, 64 substitutions per id,
48 MiB output cap; longest-id-first fixes the `img1`/`img10` prefix
collision.

### H8 — Attachment "open" launched sender-controlled file types (Fixed)
Any attachment was written to Downloads and handed to a launcher;
`.exe`/`.lnk`/`.hta`/`.desktop` run, `.html`/`.svg` render with script
at a `file://` origin outside the reader sandbox; bidi overrides
spoofed the displayed name. Launch-unsafe types are now saved but not
opened (the IPC result says so), filenames strip bidi controls and the
full Windows reserved set, reserved device names are prefixed, and
Windows files get a `Zone.Identifier` ADS.

### H9 — Host webview ships without a CSP (Open)
`tauri.conf.json` has `"csp": null` (a documented v0.1 blocker).
Dioxus escapes all interpolations and nothing uses
`dangerous_inner_html`, so there is no injection today; a CSP is
defence in depth. Not changed here because `srcdoc` iframes inherit
the parent policy and the reader relies on `img-src https: http:` and
inline script — the right CSP needs a GUI test pass on webkit2gtk.
Suggested: `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'
'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self'
data: https: http:; connect-src ipc: http://ipc.localhost; frame-src
'self' data:` then verify the reader still renders.

## Medium

Fixed:
- **M1** Account removal with an empty id wiped the whole blob store
  (`root.join("")`). Guarded in the command and in
  `BlobStore::delete_account`.
- **M2** Rotated refresh token discarded when the keychain write
  failed → account locked out. Token is returned regardless; the
  failure is logged.
- **M3** OAuth loopback accepted exactly one connection with no read
  timeout and no response on error: a browser preconnect, a
  `/favicon.ico` probe or a silent peer failed or hung the flow.
  Accept loop with per-connection deadline, 404 for non-redirects,
  a page for provider denials.
- **M4** Thread ids were 32-bit random (~25 % collision chance by 50k
  threads; a collision aborts the whole `apply_chunk` tx). Now 128-bit.
- **M5** A failed CONDSTORE `CHANGEDSINCE` fetch still advanced the
  modseq cursor, silently losing flag changes. Cursor is held back.
- **M6** No I/O timeouts on IMAP connect/TLS/auth or IDLE `DONE`; a
  half-open socket wedged the per-account session mutex. 30 s bounds.
- **M7** FTS index lost forever if the process died mid
  history-pull. Repaired at startup (`ensure_fts_index`).
- **M8** Deleted/pruned messages left their body blobs on disk forever.
  Blobs are deleted alongside rows (sync + `messages_delete`).
- **M9** User search text with `:`, `(`, quotes, `-`, `AND` reached
  Tantivy unescaped → parse errors / empty results. Operators are a
  whitelist; everything else is quoted and escaped.
- **M10** Draft attachment paths were accepted verbatim from the
  webview and read from disk on every autosave — a renderer foothold
  could exfiltrate any local file. Paths must come from the picker
  this session or already be on the draft row.
- **M11** `mailto:` links were dropped whenever QSL was already
  running (single-instance plugin lacked the `deep-link` feature);
  the path component was not percent-decoded.
- **M12** Notification master / per-account toggles were never read.
- **M13** Devtools compiled into release builds; secondary windows
  forced `.devtools(true)`.
- **M14** UI panics: `has_prefix` byte-sliced CJK subjects on
  Reply/Forward; `parse_addrs` built an inverted range for `foo> <bar`.

Open:
- **M15** Token refreshes are uncached and unserialised per folder
  watcher; with a rotating-refresh-token provider two concurrent
  refreshes can race and lock the account out. Route all three call
  sites in `backend_factory.rs` through one per-account
  `Mutex<Option<TokenSet>>` and `access_token_for`.
- **M16** The typed email is never verified against the OAuth grant
  (`login_hint` only); approving as a different Google account stores
  the token under the wrong label and every IMAP login fails. Add
  `openid email` and compare `id_token.email`, or read the JMAP
  session `username`.
- **M17** JMAP incremental sync stamps account-wide `Email/changes`
  results with the folder being synced and ignores `hasMoreChanges`;
  rows are misfiled then pruned. Needs `Email/get` with `mailboxIds`
  (or `Email/queryChanges` with `inMailbox`) and a `hasMoreChanges`
  loop. JMAP message ids are also not account-scoped (server ids are
  unique per account; cross-account collision is not expected on
  Fastmail but is not guaranteed by the spec).
- **M18** Send/discard leave orphan copies in the server Drafts
  folder (pending `save_draft` row runs after the local row is gone,
  `server_id` never destroyed). Delete the dedup row and enqueue a
  destroy on send/discard.
- **M19** Undo-send: Discard/close during the countdown doesn't cancel
  the send; the detached future reads dropped signals (Dioxus panic)
  or re-creates and sends the discarded draft. Clear
  `undo_send_pending` on discard/close and snapshot the form at click.
- **M20** `enqueue_dedup` overwrite vs in-flight drain: an autosave
  during a `save_draft` dispatch is overwritten-then-deleted and never
  uploaded; `record_failure` uses a stale `attempts`. Add a
  generation column and `DELETE … WHERE id=? AND generation=?`.
- **M21** `submit_message` is retried after a send that succeeded but
  whose row delete failed (duplicate send); `InvalidInput` errors are
  retried 5× instead of DLQ'd. Record a "submitted" marker before
  deleting; map `InvalidInput`/`Parse` to immediate DLQ.
- **M22** `sync_db` mutex is held across network I/O in the outbox
  drain (latency stall, not deadlock). Lock only around
  `list_due`/`delete`/`record_failure`.

## Low (selected)

Fixed: hostile `expires_in` could panic (`chrono::Duration::seconds`
overflow) — clamped; `data:`/`cid:` allowed on `href` — dropped;
`mark_blocked_images` misparsed `>` inside attribute values — quote-aware
tag end; CLI folder arguments now scoped like the backend expects.

Open (no code change here):
- `Debug` derives on `ImapDialParams` / `JmapDialParams` /
  `LoopbackResult` / wire token structs would print secrets if ever
  `{:?}`-logged (none are today). Use redacting `Debug` impls.
- Reconnect backoff in `imap_idle.rs` / `jmap_push.rs` never resets
  and `ConnectionRestored` is emitted before the redial succeeds.
- `fetch_raw_message` takes the first FETCH response without checking
  it is the requested UID (unsolicited FLAGS responses produce a
  spurious "no body" error).
- `UID FETCH {uidnext}:*` re-fetches the newest message every cycle
  (RFC 3501 §6.4.8).
- Reconnect-in-place hardcodes port 993; `select()` instead of
  `select_condstore()` relies on server defaults for HIGHESTMODSEQ.
- `delete_messages` on JMAP is `Email/set destroy` (permanent); on
  Gmail `\Deleted + UID EXPUNGE` archives unless the user's IMAP
  setting says otherwise. Consider routing UI "delete" to
  `move_messages(Trash)` when a Trash role exists.
- History-sync cancel→start race orphans the new job's cancel token
  (`drop_canceller` should `Arc::ptr_eq`); persist-error path leaves
  the row `running`.
- `unwrap()` on DB timestamps in `drafts.rs` / `history_sync.rs`
  row mappers.
- DB / blob files created with default (umask) permissions on Linux.
- `in:` label filter LIKE pattern doesn't escape `%`/`_`.
- `batch_find_existing` builds an unchunked `UNION ALL`; folders that
  gained > ~32k messages between syncs fail every cycle.
- `threads.message_count` never decremented on delete; `root_message_id`
  can dangle.
- Concurrent `BlobStore::put` for the same key share one `.tmp` path.
- `webbrowser::open` is the wrong launcher for `mailto:` and for
  files on Windows (always resolves the http handler); consider the
  `open` crate or `tauri-plugin-opener` for files.
- `client_secret` is baked into the binary via `env!` (acceptable for
  a native app per RFC 8252 §8.5, but the docs call it a confidential
  client — it isn't). `build.rs` doesn't reject newlines in `.env`
  values (directive injection; maintainer-controlled).
- PII at `info` level: mailto recipient/subject, notification title,
  every settings value, search queries at debug.
- `deny.toml` still carries ~75 Servo-era MPL exceptions and
  advisory ignores justified by a renderer that was removed.
- `release.yml` interpolates `${{ inputs.tag }}` directly into bash;
  several actions are floating tags while cargo-deny is SHA-pinned.
- `deep-link:allow-register/unregister` capability lets the webview
  register any scheme (redundant with the Rust commands).
- `ui_log` IPC has no size/rate cap.
- `reply_all_cc` drops the original `From` when `Reply-To` is set;
  `inline_cid` is a weak additive hash (inline images can cross-wire).
- Non-ASCII attachment filenames are RFC 2047-encoded inside
  `filename=""` instead of RFC 2231 `filename*=`.

## Checked and found sound

- OAuth: PKCE S256 with CSPRNG verifier and state, state checked
  before exchange, loopback bound to `127.0.0.1:0`, HTTPS endpoints,
  rustls with no verification bypass, reqwest timeouts, refresh tokens
  only in the OS keyring, token types redact `Debug` and zeroize,
  RFC 7009 revoke on remove.
- TLS everywhere: rustls + `webpki_roots`, SNI/hostname verification,
  implicit TLS on 993/465 or STARTTLS `Required`; no plaintext
  fallback, no `danger_*` flags.
- IMAP command injection: all mailbox names pass through async-imap's
  `validate_str` (quoted, escaped, CR/LF rejected); UID sets are
  numeric; every mutating path SELECTs and checks UIDVALIDITY first
  and uses `UID` commands only.
- SQL: every `format!` interpolates placeholder indexes or constant
  identifiers; all user/server strings are bound. No injection.
- Blob paths: percent-encoding of `/ \ : < > " | ? * %`, controls and
  leading `.` — no traversal from server-controlled ids.
- Reader: iframe is `sandbox="allow-scripts"` only (opaque origin);
  srcdoc CSP keeps `default-src 'none'`, `base-uri 'none'`,
  `form-action 'none'`; the parent `message` listener checks
  `origin === 'null'`; `open_external_url` allow-lists http(s)/mailto
  and passes the URL as argv, not through a shell.
- ammonia 4.1.2 removes `script style iframe object embed form svg
  math meta base link video source picture noscript head title`,
  `on*` handlers, `javascript:` and relative `src` in block mode.
- Tauri capabilities expose only app commands; no shell/opener/fs/http
  plugins. mailcli `reset` deletes only `qsl.db*` and `blobs/`, prompts
  unless `--yes`, never prints tokens. CI uses `pull_request`, echoes
  no secrets.
